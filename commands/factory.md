description: Connect this machine and this repository to factory — login, link, status, backfill, repo-hours, logout
argument-hint: login | link [project id] | status | backfill | repo-hours | logout
---

Connect this machine to factory, link the current repository to its factory project, and recover work time that capture lost. The token is the personal credential that lets crew send captured work time to factory and read its backlog.

Run each action from the project root. Relay the script's result in one or two plain sentences. The token never appears in any output. When someone offers to paste a token into the chat, ask them to keep it out of the conversation and use `login` instead. Pasting a token by hand into `~/.crew/factory-token` or `FACTORY_TOKEN` remains the fallback, documented in the plugin's `docs/en/factory.md`.

- **login** — `node "${CLAUDE_PLUGIN_ROOT}/scripts/factory-login.js" login`. Run it in the background or with a timeout of at least six minutes: it waits until the person approves in the browser. It opens factory in the browser; tell the person to read what capture records and approve there, then come back to the chat. If the browser did not open, show them the printed link. The token goes straight from factory to a file only they can read. Time queued while an earlier token was expired is sent right away when it belongs to the same person on the same factory; relay that line too. The login does not set `FACTORY_TOKEN` nor register factory's MCP server: when it connects it prints the registration commands, which read the token from that file. Offer to run them and wait for an explicit yes (or let the person run them in their terminal); run exactly the printed lines, verify only with `claude mcp list`, and say the tools appear in sessions started afterwards. Never register the server with `${FACTORY_TOKEN}`, never read or print the token file, never run `claude mcp get factory` and never show `~/.claude.json`: the registration holds a copy of the token. When the login prints no command (an address it will not put in a shell line), point to step 3 of `docs/en/factory.md`.
- **link** — `node "${CLAUDE_PLUGIN_ROOT}/scripts/factory-link.js"` finds the project from the repository's git remote. When factory has the repository on one of the person's projects, it writes the link into `crew.json` by itself, as the person asked: relay what it did and remind them to commit `crew.json`. Otherwise it prints one of these, and you follow it:
  - **A project the person is not part of**: relay the sentence as printed, without guessing which project. Offer to ask for access; only after they say yes, run it with `--request-access`.
  - **A list of the person's projects** (no match, no remote, or a remote factory cannot read): show it and ask which one this repository works for, saying that confirming also registers the repository on that project in factory when they may. After they confirm, run it with the chosen project id: `node "${CLAUDE_PLUGIN_ROOT}/scripts/factory-link.js" <project id>`. Pass the id, never a position in the list. It also registers the repository on that project when the person may; relay that line.
  - **An offer to create a project** (only for people who may create them): if they want one, run it with `--create` to list the clients they can choose. Show the client, the name (default: the repository's) and the currency code the script printed, and only after they confirm all three, run `--create --client <client id> --name "<name>"`, adding `--currency <code>` when they chose another one or the script printed no default.
  Add `--replace` only when the person agreed to change an existing link, and `--set-environment` only when they agreed to write this machine's environment into `crew.json`.
- **status** (the default with no argument) — `node "${CLAUDE_PLUGIN_ROOT}/scripts/factory-login.js" status`. Says which factory this machine talks to, as whom, when the token expires, how much captured time waits on this machine, and which project the current repository is linked to.
- **backfill** — `node "${CLAUDE_PLUGIN_ROOT}/scripts/factory-backfill.js"` rebuilds this repository's work time before it was linked to factory, from the person's local Claude Code transcripts, and shows a summary per day. Run it only when the person asks, typically once after linking a repository they already worked in. Days live capture already sent are corrected in factory: never suggest backfill to fix turns already captured. Show the summary as printed. Add `--since YYYY-MM-DD` only with a date the person gave you. Add `--send` only after the person explicitly says yes to the summary in the chat, never on your own initiative.
- **repo-hours** — loads into factory the hours this repository recorded: the Started/Finished of each milestone in the `## Estimation` tables and the Duration of each work log, each row with the author of the commit that wrote it. Factory decides whose each row is from that email; never name a person yourself. Steps, in order, never skipping the dry run:
  1. `node "${CLAUDE_PLUGIN_ROOT}/scripts/factory-repo-hours.js"` reads the repository and writes a JSON file (the path is printed). Relay the summary. Never read the files yourself and never edit the JSON.
  2. `find_project_by_repo` with the printed repository. Without `match: "yours"`, stop and offer `link`.
  3. For each entry of `requirements` in the JSON: `upsert_requirement` with that project id, its `code`, `externalKey`, `title` and `milestones` (each `code`, `title`, `estimatedHours`). If factory asks for a package, ask the person which one.
  4. For each entry of `batches`: `import_repo_hours` with it as is (a dry run by default). Show the person the result: hours per person and month, whether each person gets them as their own (`own`) or waiting for their confirmation (`pending`), and the counts of `outcomes`. Rows `no_person` mean emails factory does not know: each person registers theirs in factory, Mis horas → Correos de git.
  5. Only after the person says yes in the chat: the same `import_repo_hours` calls with `dryRun: false` and a new `retryKey` per batch. Relay `derivedDays` and `retired`.
- **logout** — `node "${CLAUDE_PLUGIN_ROOT}/scripts/factory-login.js" logout`. Revokes the token in factory and removes it, and any queued time, from this machine. It also prints how to remove the registered MCP server, which keeps its own copy of the token.

Which factory is used: the project's `crew.json` `factory` block picks `environment` (`prod` by default, or `dev`) or a `url`. On a single machine, `CREW_FACTORY_ENV` or `CREW_FACTORY_URL` override it.
